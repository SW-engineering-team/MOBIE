# MOBIE 테스트 보고서

## 1. 테스트 목적

본 문서는 영화/책 추천 기록 앱 **MOBIE**가 요구사항 분석과 설계 문서에 따라 구현되었는지 확인하기 위해 작성하였다.  
테스트 범위는 CRUD 기능, 필터/정렬 기능, 추천 기능, 입력값 검증, 4차 회의에서 도출된 개선사항 반영 여부를 포함한다.

---

## 2. 테스트 대상

- 프로젝트명: MOBIE
- 대상 산출물: `output/process-based-prompting`
- 실행 방식: 브라우저에서 `index.html` 실행
- 저장 방식: 브라우저 `localStorage`
- 주요 파일:
  - `index.html`
  - `styles.css`
  - `app.js`

---

## 3. 테스트 기준

테스트 기준은 `docs/requirements.md`, `docs/design.md`, 4차 및 5차 회의록을 바탕으로 정하였다.

- 사용자는 영화 또는 책 기록을 추가할 수 있어야 한다.
- 사용자는 등록된 기록을 조회, 수정, 삭제할 수 있어야 한다.
- 사용자는 영화/책 유형에 따라 기록을 필터링할 수 있어야 한다.
- 사용자는 최신순, 별점순, 제목순으로 기록을 정렬할 수 있어야 한다.
- 별점 4점 이상 기록은 추천 목록에 표시되어야 한다.
- 장르를 선택하면 해당 장르의 추천 항목만 표시되어야 한다.
- 필수 입력값이 누락되면 오류 메시지가 표시되어야 한다.
- 추천 여부를 체크했을 때만 추천 이유 입력란이 표시되어야 한다.
- 추천 기준은 사용자가 이해할 수 있도록 화면에 표시되어야 한다.

## 6. Direct prompting 결과물 대비 테스트 관점의 차이

Direct prompting 결과물은 빠르게 실행 가능한 단일 HTML 형태의 앱을 만들 수 있었지만, 요구사항과 테스트 항목이 명확히 연결되지는 않았다. 특히 상세 보기, 수정, 별점 기반 추천 목록, 장르별 추천 필터, 추천 이유 입력 조건은 충분히 반영되지 않았다.

프로세스 기반 결과물은 요구사항 문서와 설계 문서에 정의된 기능을 기준으로 구현되었기 때문에 테스트 항목을 체계적으로 작성할 수 있었다. 또한 4차 회의에서 발견된 문제를 5차 회의에서 수정하고 다시 검증하면서, 단순 구현을 넘어 품질 관리 과정까지 증빙할 수 있었다.

---

## 7. 결론

MOBIE의 핵심 요구사항인 CRUD, 필터링, 정렬, 추천 기능은 정상적으로 동작하였다.  
4차 회의에서 도출된 추천 이유 입력 방식과 추천 기준 설명 문제도 수정되었으며, 테스트 결과 모두 통과하였다.

다만 현재 앱은 정적 웹앱으로 브라우저 `localStorage`에 데이터를 저장하기 때문에, 여러 기기 간 데이터 공유나 서버 기반 사용자 관리는 지원하지 않는다. 이 부분은 과제 범위 밖으로 판단하고, 본 프로젝트에서는 프로세스 기반 바이브코딩의 효과를 확인하기 위한 핵심 기능 구현과 품질 관리 증빙에 초점을 두었다.
