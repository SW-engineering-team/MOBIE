# 프로젝트 운영 규칙

## 프로젝트 개요

- 프로젝트명: 영화/책 추천 기록 앱
- 목표: 바이브코딩을 활용하여 작은 규모의 소프트웨어를 개발하되, 요구사항 분석부터 품질 관리까지의 개발 프로세스를 명확히 적용하고 기록한다.
- 주요 증빙 자료: 회의록, 요구사항/설계 문서, AI 프롬프트 기록, 소스 코드 커밋, 테스트 기록, 실행 화면 캡처, 최종 보고서

## 팀 운영 규칙

- 주 2~3회 회의를 진행하고, 회의 후 반드시 회의록을 작성한다.
- 회의록에는 회의 일자, 참석자, 논의 안건, 주요 결정 사항, 할 일, 다음 회의 안건을 기록한다.
- 토의 내용과 의사결정 과정은 GitHub에 남겨 추후 프로세스 적용 과정을 검증할 수 있도록 한다.
- 제출 마감 직전에 작업을 한꺼번에 몰아서 진행하지 않고, 프로젝트 기간 동안 작고 지속적인 커밋을 남긴다.
- 요구사항이나 설계 결정이 변경될 경우, 기존 결정을 조용히 덮어쓰지 않고 변경 이유를 함께 기록한다.
- 회의록 작성 시 가능하면 사실, 결정 사항, 의견을 구분하여 기록한다.

## 사용 예정 AI 도구

본 프로젝트에서는 바이브코딩과 문서화 보조를 위해 다음 AI 도구를 사용한다.

- ChatGPT/Codex: 요구사항 정리, 설계 논의, 코드 생성, 리팩터링 보조, 테스트 케이스 초안 작성, 보고서 초안 작성
- GitHub Copilot 또는 유사한 코딩 보조 도구: 에디터 내 코드 자동완성 및 구현 보조
- 기타 AI 도구: 사용 목적과 결과를 `docs/ai-prompts.md`에 기록하는 경우에만 사용한다.

## AI 활용 원칙

- AI의 제안은 최종 결정이 아니라 초안으로 취급한다.
- AI가 생성한 요구사항, 설계안, 코드, 테스트 케이스는 팀원이 검토한 뒤 수용 여부를 결정한다.
- 중요한 AI 활용 과정은 `docs/ai-prompts.md`에 요약하여 기록한다.
- 프롬프트의 목적, 사용한 AI 도구, 유용했던 결과, 팀이 수용/수정/반려한 내용을 함께 기록한다.
- API 키, 비밀번호, 개인정보, 기밀 정보는 AI 프롬프트에 포함하지 않는다.
- AI가 생성한 코드로 인해 버그나 품질 문제가 발생한 경우, 문제와 수정 과정을 테스트 보고서 또는 교훈 문서에 기록한다.

## 개발 프로세스 규칙

본 프로젝트는 가벼운 반복형 개발 프로세스를 따른다.

1. 요구사항 분석
   - 대상 사용자, 사용자 문제, 기능 요구사항, 비기능 요구사항을 정의한다.
2. 설계
   - 주요 화면, 데이터 모델, 사용자 흐름, 기술 선택 사항을 정의한다.
3. 구현
   - 기능을 작은 단위로 구현하고, 의미 있는 변경마다 커밋한다.
4. 테스트
   - 주요 기능을 수동으로 테스트하고 결과를 문서화한다.
5. 품질 관리
   - 사용성, 코드 가독성, 버그, AI 생성물의 품질을 검토한다.
6. 교훈 정리
   - 잘된 점, 어려웠던 점, 프로세스 적용이 바이브코딩에 준 영향을 정리한다.
